# FinancerAI

FinancerAI is a Python and Streamlit application for exploring financial data from Excel files through an AI-assisted interface. It combines tabular data processing, OpenAI API integration, voice interaction, and automated tests in a modular project structure.

## Features

### Excel data processing

- Upload `.xlsx` and `.xls` files through the Streamlit interface.
- Validate that an uploaded file is present and no larger than 10 MB.
- Read the workbook with Pandas.
- Reject empty DataFrames and files with fewer than two columns.
- Preview records and display the number of rows, columns, and null values.

### AI-assisted analysis

The application sends the loaded financial data to OpenAI to generate:

- Financial summaries
- ISR-oriented responses
- IVA-oriented responses
- Fiscal risk observations
- Financial recommendations

The ISR and IVA items are currently responses generated by the AI model. There is no deterministic tax calculation connected to the main application flow. The model is prompted to respond in the context of accounting and legislation in Guatemala; these responses should not be treated as a substitute for professional tax advice.

### Voice interaction

Users can record a financial question, obtain a response based on the loaded data, and listen to the response as audio:

1. Capture audio through `streamlit_mic_recorder` or Streamlit's native audio input.
2. Transcribe the recording through the OpenAI API using the `whisper-1` model. Whisper is not executed locally in this project.
3. Send the transcription and available financial context to OpenAI.
4. Generate an audio response through OpenAI Text-to-Speech using the `tts-1` model.

Conversation history is kept in the current Streamlit session.

## Architecture

```text
FinancerAI/
├── app.py
├── backend/
│   ├── excel_processor.py
│   ├── tax_calculator.py
│   └── validations.py
├── frontend/
│   ├── dashboard.py
│   ├── upload_view.py
│   └── voice_view.py
├── ia/
│   ├── openai_client.py
│   ├── openai_service.py
│   ├── prompts.py
│   └── speech_service.py
├── tests/
│   ├── conftest.py
│   ├── test_ai.py
│   ├── test_audio.py
│   └── test_excel.py
├── .env.example
├── requirements.txt
└── README.md
```

The main responsibilities are separated as follows:

- `backend/`: Excel processing, input validation, and an isolated helper for calculating totals of numeric columns.
- `frontend/`: Streamlit interface components.
- `ia/`: OpenAI client, financial analysis service, and audio processing.
- `tests/`: tests for Excel-related behavior, AI-related placeholder behavior, and audio utilities.

`backend/tax_calculator.py` is not connected to the main application flow; its current implementation only calculates totals for numeric DataFrame columns. The definitions in `ia/prompts.py` are also not imported by `ia/openai_service.py` at present.

## Technology stack

- Python 3
- Streamlit
- Pandas for tabular data and Excel loading
- OpenPyXL and `xlrd` as Excel-related dependencies declared in `requirements.txt`
- OpenAI API for financial analysis, transcription, and text-to-speech
- `streamlit-mic-recorder` and Streamlit audio input for voice capture
- Pytest for automated tests
- Python Dotenv for environment-based configuration

NumPy is listed in `requirements.txt`, but it is not imported directly by the application code.

## Application flow

### 1. Upload and validate data

The user uploads an Excel file. The application checks that the upload is present, does not exceed 10 MB, produces a non-empty DataFrame, and contains at least two columns.

### 2. Inspect the dataset

The dashboard displays the uploaded records and basic statistics: row count, column count, and total null values.

### 3. Request an AI analysis

The application converts the DataFrame to text and sends it to OpenAI through the chat completions API. The returned text is displayed as the financial analysis.

### 4. Use the voice assistant

The voice flow is:

```text
Voice input
    ↓
OpenAI transcription API (whisper-1)
    ↓
Financial data + user question
    ↓
OpenAI chat analysis (gpt-4o)
    ↓
Text-to-speech API (tts-1)
    ↓
Audio response
```

## Installation

Create the project environment and install the dependencies declared by the project:

```bash
python -m venv .venv
```

On Windows, install the dependencies with the Python interpreter from the virtual environment:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

On macOS or Linux, use:

```bash
.venv/bin/python -m pip install -r requirements.txt
```

## Configuration

Copy `.env.example` to `.env` in the project root and provide an OpenAI API key:

```env
OPENAI_API_KEY=your_api_key
```

The application loads the key from the environment through Python Dotenv. The local `.env` file should not be committed or shared.

## Running the application

Start the Streamlit application with the Python executable from `.venv`:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

By default, Streamlit serves the application at:

```text
http://localhost:8501
```

## Testing

The repository includes test files for:

- Excel-related behavior: `tests/test_excel.py`
- AI request construction and response handling with mocks: `tests/test_ai.py`
- Audio utilities and metadata handling: `tests/test_audio.py`

Run the complete suite with:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Run an individual test file with:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_excel.py
```

The test suite can run without credentials or network access because the OpenAI interactions are mocked. These tests verify request construction and local response handling; they do not validate a live OpenAI integration or credentials.

## Security considerations

- The OpenAI API key is read from `OPENAI_API_KEY` rather than hard-coded in the source code.
- `.env.example` contains the configuration template; `.env` and `.venv` are intended to remain local and should not be published to GitHub.
- Uploaded files receive the basic size and structure validation described above.
- Production deployments should add controls appropriate for the sensitivity of financial information and the use of external AI services.
